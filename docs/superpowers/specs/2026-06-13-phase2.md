   must not cause issues. No third-party code in a **core path** (tool access,

   abandoned.

## 1. Cross-session research-state memory — P2, BUILD

A long arc (`explore → plan → analyze → review → submit`) loses its thread on
context compaction. Persist a **small, auditable, tool-derived** snapshot at
`session_before_compact`, and re-inject it as clearly-labelled *background*
context on the first turn after compaction so the agent never re-asks "which
project are we on?". The block carries **only counts + identifiers — never claim
text or a verdict** — so an unverified claim can never be laundered back in as
fact (calibrated trust / `tierForEvidence` untouched).

### Files
- **Create** `lib/session-state.ts` — pure, strip-safe: `ResearchStateSnapshot`
  interface + `buildSnapshot(...)` (clamp/coerce/omit) + `formatReinjection(s)`.
- **Create** `extensions/beril-memory.ts` — three event handlers + a checkpoint
  cache; registers **no tool**.
- **Create** `test/session-state.test.ts` (node --test) + `tests/test_cli_session_state.py` (pytest).
- **Modify** `beril_cli/lifecycle_cmd.py` — add a `session-state` action to
  `run_lifecycle` (after the `current` early-return and the `if not args.project`
  guard, inside the `try` so a missing `beril.yaml` → `LifecycleError` → rc 2).
- **Modify** `beril_cli/cli.py` (~line 107) — add `"session-state"` to `choices`;
  add `--set <json>` and `--get` flags.
- **Modify** `extensions/beril-checkpoint.ts` — ONE line in `execute` before the
  `return`: `pi.events.emit("beril:checkpoint", { title: params.title, choice });`.

### Design (verified APIs)
- `session_before_compact` (`types.d.ts:425`, registered `:814`, result
  `{ cancel?, compaction? }` `:772`) — **return `undefined`** to neither cancel
  nor override compaction; run the flush as an async side-effect. Ignore
  `event.preparation`/`branchEntries`/`signal` — we snapshot *tool* state, not
  the conversation.
- `session_compact` (`types.d.ts:433`, registered `:815`, fires AFTER compaction)
  — arm a one-shot module flag `pendingReinject = true`. The only reliable
  "a compaction just happened" signal.
- `before_agent_start` (`types.d.ts:491`, registered `:822`, result
  `{ message?, systemPrompt? }` `:760`; "If multiple extensions return this, they
  are chained" `:762`) — on the first post-compaction turn, append the formatted
  block to `event.systemPrompt`. Use **`systemPrompt`, not `message`** (a message
  renders in the transcript and reads as a fresh finding). Same pattern as
  `extensions/beril-conduct.ts:23-26`; Pi chains the conduct + memory appends.

**State ownership (the crux).** `beril.yaml` is written only by Python.
`save_project` (`lifecycle.py:62-69`) writes `_KEY_ORDER` keys first, then appends
any unknown top-level key in insertion order — so a new `research_state` block
**round-trips losslessly and lands after the canonical keys** (incl.
`approval`/`submissions`). TS persists exclusively via `berilExec`; it never
touches YAML. (The "CLI JSON goes through a file not stdout" gotcha does **not**
apply — that is specific to the Spark/notebook subcommands where `[hub]` pollutes
stdout; `lifecycle current/set/status` already `json.dump(..., sys.stdout)`.)

**New Python surface** `beril lifecycle session-state <project> --set <json> | --get`:

```python
if args.action == "session-state":
    proj = load_project(project_dir)                  # no beril.yaml -> LifecycleError -> rc 2
    if args.get_state:
        json.dump(proj.get("research_state", {}), sys.stdout); sys.stdout.write("\n"); return 0
    if args.state_json is None:
        print("session-state requires --set <json> or --get.", file=sys.stderr); return 2
    try:
        block = json.loads(args.state_json)
    except json.JSONDecodeError as exc:
        print(f"invalid --set JSON: {exc}", file=sys.stderr); return 2
    if not isinstance(block, dict):
        print("--set must be a JSON object.", file=sys.stderr); return 2
    block["updated_at"] = _now()                       # server-stamped
    proj["research_state"] = block                     # appended after canonical keys by save_project
    save_project(project_dir, proj)
    json.dump({"research_state": block}, sys.stdout); sys.stdout.write("\n"); return 0
```

*Optional optimization (recommended):* let this action resolve the active project
itself when `args.project` is absent (fall back to `_find_current_project`), so
the TS flush is **one** subprocess (`session-state --set`) instead of two
(`current` then `set`).

**What we flush** (`lib/session-state.ts`, all inputs the TS side already has cheaply):

```ts
export interface ResearchStateSnapshot {
  project: string;
  phase: string;            // lifecycle status, e.g. "analysis"
  step: string;             // currentStep(phase) ?? ""   (currentStep returns string | undefined)
  claims: { total: number; supported: number; refuted: number };
  lastCheckpoint?: string;  // <= 160 chars, single line: title + " -> " + choice
  note?: string;            // <= 240 chars, single line, OPTIONAL — omitted in v1
}
```

- `project` + `phase` ← `berilExec(pi, ["lifecycle","current"])` (same call as
  `beril-env.ts` `seedActiveProject`).
- `claims` ← read `RESEARCH_PLAN.md` + `REPORT.md`, then `parseClaimLedger`
  (`lib/claim-ledger.ts:178`) → `tallyClaims` (`lib/claim-ledger.ts:31`). *(Note
  the line numbers are 178/31, the reverse of an early draft.)* Same pure parse as
  `beril-env.ts` `readClaimTally`; never throws.
- `step` ← `currentStep(phase)` (`research-steps.ts:58`, returns
  `string | undefined` → coerce to `""`).
- `lastCheckpoint` ← the `beril:checkpoint` bus broadcast (one added line in
  `beril-checkpoint.ts`); `beril-memory` caches the latest in a module var. A
  tool-derived fact (the scientist's actual choice), not model prose.
- `note` ← **omitted in v1** (keeps the block fully tool-derived/auditable).

**Re-injection text (background, NOT findings):**

```
[beril cross-session context — orientation only, NOT established findings]
Resuming project "<project>" at the <step> step (lifecycle: <phase>).
Claim ledger so far: <total> claim(s), <supported> supported, <refuted> refuted
(read-only tally; re-verify before relying on any of them).
Last checkpoint decision: <lastCheckpoint>.
Treat the above as where we left off, not as proof. Re-open the plan/report and
re-run checks before asserting any result as settled.
```

**Handlers** (`extensions/beril-memory.ts`): `beril:checkpoint` listener caches
`title -> choice` (clamped 160); `session_before_compact` flushes (fail-closed on
`!ctx.isProjectTrusted()`, best-effort `try/catch`, returns `undefined`);
`session_compact` arms `pendingReinject`; `before_agent_start` short-circuits
`if (!pendingReinject || !ctx.isProjectTrusted()) return undefined` **before any
`berilExec`** (zero per-turn cost), then reads the snapshot **back from
`beril.yaml` via `--get`** (the store is the source of truth — compaction can fire
in a resumed session that never flushed) and appends `formatReinjection(snap)` to
`event.systemPrompt`.

**Safety / headless / glyphs.** Not destructive (writes a non-authoritative
annotation block, not lifecycle state or remote data) → correctly outside
`lib/destructive.ts` and the beril-safety gate; project-trust guard still applies
(fail-closed). Runs headless (no `hasUI` gate); the one-shot flag prevents repeat
injection. No tool, no card → **no `renderResult` / no glyph surface**;
re-injection is plain ASCII prose.

### Test plan
- node --test (pure): `buildSnapshot` derives `step` via `currentStep`
  (`"analysis" → "review"`), coerces unknown phase → `""`, copies the tally;
  clamps `lastCheckpoint`≤160 / `note`≤240 and strips newlines; omits absent keys;
  `formatReinjection` contains the project id + step + literal counts, contains the
  "NOT established findings" + "re-verify" guard strings, and contains **no claim
  hypothesis text** (the anti-laundering invariant); deterministic + length-bounded.
- pytest (`tests/test_cli_session_state.py`, mirror `test_cli_lifecycle_*`):
  `--set` writes + round-trips `research_state` and stamps `updated_at`; **key
  order preserved** (`research_state` after `project_id`/`status`/`engine` and
  after any pre-existing `approval`); `--get` emits the block (or `{}`); `--set`
  non-JSON → rc 2 "invalid"; `--set` a JSON array → rc 2 "must be a JSON object";
  on a project with no `beril.yaml` → rc 2; a pre-existing `approval` block survives.

### Must-confirm-live (the one real risk)
Whether Pi **awaits** the async `session_before_compact` handler before compacting
is not provable from `.d.ts` (the handler type permits `Promise<R|void>` at

0.79.1 session. The design **tolerates a late flush** — re-injection reads from the
store on the next turn — so worst case the snapshot lands a turn late, which is
harmless.

### A. `lit_stance` abstract fetch — `beril-literature.ts:330-334`
Replace the sequential `for (const r of records)` await chain:

```ts
export const LIT_FETCH_CONCURRENCY = 6; // bounded sockets queued at the shared gate; NOT a wire-rate knob
const settled = await parallelMap(records, LIT_FETCH_CONCURRENCY, (r) =>
```

`parallelMap` returns `Settled<O>[]` in **input order** (`parallel-map.ts:3-4,16,24`),
so `settled[i]` aligns with `records[i]` — the surrounding `.map((record, i) => …)`

### C. `/literature-review` verify-on-write — `beril-literature.ts:376-391`
Replace the unbounded `Promise.all(records.map(...))`:

```ts
export const LIT_VERIFY_CONCURRENCY = 6;
const settled = await parallelMap(records, LIT_VERIFY_CONCURRENCY, (r) => {
  if (r.pmid) return resolveCitation(r.pmid, ctx.signal);
  if (r.doi) return resolveDoi(r.doi, ctx.signal);
  return Promise.resolve<CitationCheck>({ pmid: "", ok: true });

const checks = records.map((r, i) =>
  settled[i].ok ? settled[i].value : ({ pmid: r.pmid ?? "", ok: false, reason: "check errored" } as CitationCheck),

```

Behaviour preserved exactly: `resolveCitation`/`resolveDoi` already swallow their
own errors and return `ok:false`; a failed check is dropped from `verified` and
counted in `dropped`. `writeFile references.md` stays the single serialized step

`renderResult` error guard and the `{ stances }` / `litCard` shapes are
byte-identical, so the cards need zero changes.

**Caps as exported module consts** so tests can import + assert them; **the cap is
not load-bearing** — the gate sets the wire rate, more workers only deepen the
queue at the gate (so the honest justification for `6` is "small bounded socket
count", not "match keyed-NCBI pacing").

## 3. Live lifecycle sub-step overlay in the workflow HUD — P3, BUILD

A TUI-only overlay line **under** the existing phase rail showing progress *within*
the current lifecycle phase, derived strictly from observed `tool_execution_*`
events — **never a model-authored todo**. Bounded by a static per-phase manifest
(O(manifest), not O(tool calls)).

### Files
- **Create** `lib/ui/substeps.ts` (pure manifest + reverse index + helpers +
  `substepRail()`), `test/substeps.test.ts`.
- **Modify** `lib/ui/workflow-hud.ts` (extend `HudState`, render the line),
  `extensions/beril-env.ts` (two observers + reset-on-phase-change),
  `test/workflow-hud.test.ts` (one case + regression guard).

### Verified API foundation
- `ToolExecutionStartEvent { toolName:string; args:any }` (`types.d.ts:541-546`),
  `ToolExecutionEndEvent { toolName:string; isError:boolean }` (`:556-562`) —
  **runtime-confirmed** emitted with `args` across all modes
  (`agent-session.js:403-411/422-430`).
- `pi.on("tool_execution_start"|"tool_execution_end", handler)` (`:830,832`),
  handler `(event, ctx) => …` (`:804`). `setWidget(key, string[]|undefined,
  {placement:"aboveEditor"})` (`:96`).

### Design (strip-safe — plain interfaces + const `Record` + functions)
Manifest keyed by the **rail phase string** (`"explore"|"plan"|"analyze"` only —
`review`/`submit`/`complete`/unknown have no entry ⇒ empty overlay, correct because
review/submit run in an isolated subagent session whose tools never surface here,
`review-agent.ts:76-80`):

```ts

  explore: [ {key:"discover",label:"discover",tools:["berdl_discover","berdl_peek","berdl_feasibility"]},

             {key:"run",label:"run",tools:["notebook_run"]},
             {key:"hash",label:"hash",tools:["notebook_hash"]},
             {key:"promote",label:"promote",tools:["lifecycle_transition"]} ],

```

Pure helpers (a reverse index `toolToStep` built once at module load):
- `substepsForPhase(phase: string | undefined): SubstepState` — **must accept
  `undefined`** (`currentStep` returns `undefined`/`"complete"`); returns
  `{phase: phase ?? "", steps: []}` for any phase with no manifest entry.
- `applyToolStart(s, toolName, args): SubstepState` — look up the step; **if none,
  or already `active`, return the SAME reference** (mandatory no-op short-circuit —
  without it every tool call repaints the HUD). Else mark it `active`, mark earlier
  steps `done` (monotonic forward), `detail = detailFromArgs(...)`.
- `applyToolEnd(s, toolName, isError)` — set `done`/`failed`; same-reference no-op
  when nothing changed.
- `detailFromArgs(toolName, args)` — **treat `args` as `unknown`, guard every
  access** (`args` is typed `any`): `if (args == null || typeof args !== "object")
  return undefined;` then `notebook_run → basename(notebook)` sans `.ipynb`,
  `berdl_discover → database`, `lit_search → query` (truncated). Never throws.
- `substepRail(theme, s): string | undefined` — `undefined` when empty; else joins
  per-step glyph+label mirroring `step-rail.ts:17-22` (done `GLYPH.ok` dim, active
  `GLYPH.here` accent bold + detail, failed `GLYPH.bad` error, pending `GLYPH.pending`
  muted). **Use `glyph(name)` for rendered output, never the raw `GLYPH` const** —
  only the function downgrades under NO_COLOR.

`workflow-hud.ts`: add `substeps?: SubstepState` to `HudState`; after the rail line
and before the `Next:` hint, push `\`  ${sub}\`` only when `substepRail` returns a
value. **Zero lines added when `substeps` is absent/empty** — preserves the existing
3-test contract incl. the "exactly 1 line before any project" invariant
(`workflow-hud.test.ts:31`).

`beril-env.ts`: set `hud.substeps = substepsForPhase(currentStep(state))` in BOTH
places that set `hud.state` (the `beril:lifecycle` listener `:123-131` and
`seedActiveProject` `:220-222`). Register the two observers guarded by
`uiCtx?.hasUI`, each with the referential-equality short-circuit before `renderHud()`.
`session_shutdown` already clears the widget; `hud.substeps` dies with the closure.

### Honest limits (state these — do not paper over)

### Adopt-vs-build: BUILD (pure, ~190–240 LOC, zero deps). **Priority P3** — excellent

## 5. `/aside` — off-the-record side-channel question — P3, BUILD (not `rpiv-btw`)

Let the scientist ask the **same** session model a one-off question whose
question+answer (a) never enter the session JSONL the model replays next turn, and
(b) never enter the claim ledger.

### Persistence crux (the whole point — all verified)
- `convertToLlm` (named re-export from the package root, `dist/index.d.ts:10`) maps a
  `custom` message's content to a `role:"user"` LLM message **regardless of
  `display`** (`session-manager.d.ts:85-99`; impl confirms `case "custom" → role:"user"`).
  So `pi.sendMessage(...{display:false})` would **silently leak** the aside into LLM
  context — **unsafe**.
- `pi.sendUserMessage` "Always triggers a turn" (`types.d.ts:864`) — unsafe.
- `pi.appendEntry` → `CustomEntry` "Does NOT participate in LLM context"
  (`session-manager.d.ts:62-69`) — safe but display-only state, not an answer surface.
- **Only zero-leak route: write NOTHING to the session; render via `ctx.ui.custom`
  (`types.d.ts:116-126`), which paints an overlay and creates no `SessionEntry`.** The
  ledger stays clean automatically because it is parsed only from `RESEARCH_PLAN.md` +
  `REPORT.md` (`claim-ledger.ts:178`), which `/aside` never writes.

### Files
- **Create** `extensions/beril-aside.ts` (~45–55), `lib/aside.ts` (~50–65, the pure
  core + `ASIDE_SYSTEM` + `BRANCH_CAP` consts), `lib/ui/aside-overlay.ts` (~70–95, the
  interactive Component), `test/beril-aside.test.ts` (~60–70). **No
  `prompts/aside-system.txt`** — `prompts/` is for Pi slash-command `.md` files; the
  system prompt is a **TS const in `lib/aside.ts`**, mirroring `CONDUCT_CONTRACT`
  (`beril-conduct.ts:25`).

### Design
Handler (`pi.registerCommand("aside", …)`, handler `(args, ctx)`):
1. **Guards first, early-return** (never fall through to a real turn):
   `if (!ctx.hasUI || ctx.mode !== "tui") { ctx.ui.notify("/aside needs interactive
   mode.","error"); return; }`, empty-arg, and `!ctx.model` guards.
2. Build read-only context: `branchToContext(ctx.sessionManager.getBranch())` — keep
   only `type:"message"` entries (`session-manager.d.ts:23-26`), take the **last
   `BRANCH_CAP` (~30–40)**, map `.message` through `convertToLlm`. Nothing written back.
   (Cap is required — otherwise every `/aside` re-sends the whole conversation.)
3. **Own `AbortController`** (independent cancel; do NOT bind `ctx.signal`).
4. Open the overlay (pending mode), call the model with **no tools** and the own
   signal, push answer/error into the overlay controller, `await` dismissal. Persist
   nothing.

`lib/aside.ts` (pure, the testable seam): `ASIDE_SYSTEM` const; `BRANCH_CAP = 40`;
`branchToContext(entries): Message[]`; `runAside(deps, question, controller):
Promise<AsideResult>` where `deps = { model, getApiKeyAndHeaders, complete }` and
`complete` defaults to pi-ai **`complete`** (match the in-repo seam
`beril-literature.ts:68-72`, not `completeSimple`). Map the result: auth `{ok:false}`
→ `{ok:false}`; **`stopReason==="aborted"`** → `{ok:false, aborted:true}`;
**`stopReason==="error"`** → `{ok:false, error}`; otherwise (`"stop"`) extract text →
`{ok:true, answer}`. **There is no `"endTurn"` stop reason** — the `StopReason` union
is `stop|length|toolUse|error|aborted` (`pi-ai/dist/types.d.ts:191`). Reuse the
existing `Completer` interface shape so tests inject a fake with no network.

`lib/ui/aside-overlay.ts` (NEW interactive Component — the first in the repo): a
`Component` shown via `ctx.ui.custom<void>((tui,theme,_kb,done)=>controller,
{ overlay:true, … })`. Three modes (pending spinner glyph / answer body via
`wrapTextWithAnsi`+`truncateToWidth` / error). `handleInput` via `matchesKey`: Esc →
`controller.abort()` + `done()`; up/down scroll on overflow. Banner
`\`${glyph("here")} aside  ${question}\`` + a dim footer `not saved to the
conversation · the agent will not see this · Esc to dismiss`. Theme keys + glyphs all
valid; no new surface.

`renderResult` guard: **N/A by construction** — `/aside` is a slash *command*, not a
tool, so there is no `renderResult`, no safety-gate entry, no repro hash. The overlay
owns its own error mode.

### Adopt-vs-build: BUILD (do not pin `@juicesharp/rpiv-btw`)
`/aside` is non-core, so a clean pinned adopt would be charter-permissible, but
`rpiv-btw` fails the health bar: ~100 published versions in ~7 weeks, single
maintainer, `*` peer ranges against Pi internals (`getBranch`, a stale-session string)
that a Pi bump will silently break — and it ships raw `.ts` as a **second `pi install`
extension package** (more install surface, not fewer owned lines), not a library you
import. Read it as a blueprint; do not pin it.

### Test plan
`branchToContext` (only message entries, last `BRANCH_CAP`, via `convertToLlm`);
`runAside` happy path (inject `complete` → `stopReason:"stop"` → `{ok:true,answer}`,
assert `tools:[]` + a `systemPrompt`); auth-fail (`complete` never called); stop

invariant** (the headline guard: assert `appendEntry`/`sendMessage`/`sendUserMessage`

`session-manager.d.ts:85-99`); headless + empty-arg + no-model guards; glyph NO_COLOR
downgrade. No pytest. **The overlay's interactive behaviour (Esc-abort, scroll,
redraw) cannot be unit-tested headlessly — verify manually before shipping.**

### LOC ~170–210 owned TS (the overlay ~70–95 is the real cost) + ~60–70 test. No Python.
**Priority P3** — clean on fit/safety and mechanism-verified, but low arc value and it

## 6. Notebook parallel fan-out in `/analyze` — DEFER (do not build in Phase 2)

**Recommendation: DEFER.** The design is charter-clean and implementable, but the
substrate makes the speedup essentially unrealizable while the seam adds real
correctness risk. Ship nothing now; revisit only under the conditions below. (This
matches the independent substrate read: notebook fan-out is the lowest-value item in
the requested scope.)

### Why defer (grounded in the real substrate)
1. **Every scaffolded notebook touches the single per-user Spark master.** The scaffold
   template **always** inserts the Spark setup cell — `_setup_source()`
   (`notebook_cmd.py:118-127`) is wired into every notebook by `_build_notebook`
   (`:143-144`) and calls `get_spark_session()`. Off-cluster all sessions route to
   `metrics.berdl.kbase.us:443`; on-cluster to the in-pod master — either way one fixed
   executor pool for one user, so two "parallel" Spark notebooks time-slice the same
   executors (≈no wall-clock win, higher OOM/eviction risk).
2. **The off-cluster `ensure_hub()` spawn race is the only correctness-bearing work,
   and it is the trickiest.** `ensure_hub()` (`get_spark_session.py:60-102`) runs
   `berdl-remote spawn` + `time.sleep(40)` once per `get_spark_session()`, gated only by
   `BERDL_NO_AUTO_SPAWN`. N cold kernels race N spawns + N×40s sleeps. The "warm once,
   then fan out with `BERDL_NO_AUTO_SPAWN=1`" mitigation has **no lightweight warm-up
   entry point today** — high risk for ~zero payoff.
3. **No mechanical checkpoint to preserve.** `notebook_run` executes ALL notebooks in
   ONE subprocess (`beril-analysis.ts:94-114`); the "/analyze pauses after the first
   notebook" behaviour is only an LLM instruction string (`:134`), not machinery.

### Revisit conditions (build only when ALL hold)
(a) a notebook class exists that does **not** call `get_spark_session()` (e.g.
local-figure or literature-synthesis notebooks — needs a scaffold-template variant that
omits the Spark setup cell), **and** (b) BERDL confirms its per-user session policy
tolerates 2 concurrent Spark sessions. Until both hold, fan-out is net-negative.

### If revisited — shape (do not build now)
`beril_cli/notebook_cmd.py` `_run`: add `concurrency: int = 1`; **keep the exact
current serial loop byte-for-byte when `concurrency <= 1 OR len(targets) == 1`**; only
when `concurrency > 1` AND a separate `--independent` flag is set, run a
`ThreadPoolExecutor(max_workers=max(1, min(concurrency, 2)))` over the per-notebook
subprocess, restoring input order before the unchanged aggregation, with the warm-up +
`BERDL_NO_AUTO_SPAWN=1` env on the fanned-out subprocesses. `cli.py`: `--concurrency`
(default 1, hard cap 2) + `--independent` (fail-safe to serial; both no-ops for a named
single notebook). `beril-analysis.ts`: two `Type.Optional` params + conditional
`args.push`; everything else (the `pi.exec`, exit-2-throw, JSON parse, card + error
guard) unchanged. Independence is **human-asserted** via an `[independent]` heading
marker; any untagged notebook ⇒ serial. **LOC if built: ~90–130 owned + ~90–120 test.
Recommended: 0 LOC — defer.**

## 7. MCP bridge — DEFER → Phase 3 (build targeted free REST clients on demand instead)

**Decision: DEFER.** Pi 0.79.1 ships zero MCP (verified: no MCP symbol anywhere in
`pi-coding-agent/dist` or `pi-ai/dist`; `@modelcontextprotocol/sdk` is **not**
installed; the only extension surface is `registerTool`). A generic bridge is ~320–450
lines of **100%-owned core-path glue plus a brand-new churning SDK on the tool-access
path** — net-negative with **no concrete near-term need**, because Phase 1 already
covers literature (PubMed + Europe PMC) + arbitrary-URL read + current docs, all free
and keyless.

**Trigger that flips this to BUILD (Phase 3, scoped to ONE server):** a *live*
project's evidence chain depends on an **OAuth-only, MCP-exclusive** source with no
usable free REST — concretely a private **Synapse** project (controlled-access dataset
versions / private fileviews / provenance; the public REST plane returns 200 but the
private surface is OAuth-gated) or licensed **Wiley** full text. Owkin/BioRender are
never on the read→analyze→verify evidence path — ignore unless product scope changes.

**Why REST clients win for everything else (probed live 2026-06-13, all HTTP 200, no
key):** Open Targets GraphQL (`api.platform.opentargets.org/api/v4/graphql`), UniProt,
ChEMBL, Ensembl, KEGG (`text/plain` flat-file → a small ~90 LOC parser is genuinely
needed), STRING (200 with no auth param; identity is etiquette, not auth), Reactome,
RCSB/PDB, NCBI datasets. Each is a small free client in the **proven `lib/europepmc.ts`
pattern** (a complete keyless client in 117 LOC): pure normalizer + param/URL builder
(unit-tested) + a thin `fetch` with `AbortSignal.timeout` and the retry/backoff loop of
`lib/lit.ts:109-127`; register via `pi.registerTool` copying the `lit_search` block
(typebox params with `StringEnum([...] as const)`; `execute(toolCallId, params, signal,
onUpdate, ctx)` — the verified arg order; `renderResult` whose first line is the
mandatory error guard, helpers at `science-cards.ts:57`/`:39`); evidence stays **LOW
tier**. Read-only ⇒ not in `DESTRUCTIVE_TOOLS`, so no gate change. **Build them one at a
time when a researcher actually asks** — the two most likely first asks are Open Targets
(target prioritization on BERDL genomic data) and UniProt (protein annotation beside
microbial tables). ~70–120 LOC each.

**The decisive robustness fact (why a bridge is heavier than it looks):** the
beril-safety gate is purely name-based — `beril-safety.ts:15` returns `undefined`
(=allow) for any tool name not in `DESTRUCTIVE_TOOLS` (`destructive.ts:2,27-32`). An
auto-discovered MCP tool like `mcp__synapse__create_file` would **bypass the gate
entirely** (no confirm, no trust check, no headless block) unless re-registered under a
stable name and classified. If/when the bridge is built (Phase 3, on
`@modelcontextprotocol/sdk` ONLY — never `@codella`/`@gotgenes`, scoped to the one
triggering server, no arbitrary auto-discovery) it must: register each MCP tool under a
stable name the existing `tool_call` hook sees; **default-deny** unknown MCP tools as
destructive via `DESTRUCTIVE_TOOLS.add(name)` (a hand-maintained per-server
classification list — the ~50–70 LOC most likely to rot, the strongest reason to defer);
inherit the single existing gate so `!isProjectTrusted()`/`!hasUI` blocks apply; and add
a test proving an unclassified MCP tool is gated. The OAuth handshake (authorize-URL,
callback, token store/refresh, headless-deny) is the sole justification and the only
part the free-REST clients cannot replace.
