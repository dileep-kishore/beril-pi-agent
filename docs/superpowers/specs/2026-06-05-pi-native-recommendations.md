# Making beril-pi-agent More Pi-Native — Synthesis Report

Verified against installed `@earendil-works/pi-coding-agent` 0.78.1 and the repo at `/Users/g8k/Documents/Work/Collaborations/beril-pi-agent`.

## Executive summary

beril-pi-agent today is a thin TS Pi package that shells out to a bundled Python `beril` CLI for almost everything: every data/governance tool re-execs `beril env --json` for readiness *and then* execs its own subcommand, the literature path spins up a whole second `pi` process to expand a topic into queries, and rich-result display is hand-rolled pipe-tables and `JSON.stringify` dumps. The goal of this work is to make the workbench more Pi-native along three axes — **(1) move logic from Python to TS where it is safe and pure** (the PubMed HTTP client, the query-expansion call), **(2) lean on real Pi primitives** (`renderResult`, `registerMessageRenderer`, `setStatus`/`setFooter`, `appendEntry`, `pi.events`, `before_agent_start`, `registerFlag`, `getArgumentCompletions`, `ctx.ui.custom`), and **(3) collapse redundant subprocess hops** — all without touching the two byte-identical sha256 reproducibility primitives, the lifecycle/beril.yaml state machine, the ORCID gate, or the central safety gate. The biggest single workflow win is removing the per-tool `beril env` readiness re-exec; the biggest pure-removal win is the literature slice (drops the `httpx` Python dep entirely); the biggest UI win is a real, themed query-result card plus an always-visible BERDL+lifecycle status bar. Several adversarial verdicts forced material guardrails (GFM cell-escaping on the table card, a mandatory model fallback for `complete()`, a three-way mode branch on the confirm overlay) and **refuted two ideas outright** — `allowed-tools` skill enforcement (parsed-but-ignored in 0.78.1) and feeding two hashes to `renderDiff` (line-diff-oriented; corrupts opaque hex).

All recommendations stay strictly above the Python reproducibility/governance boundary. Every API claim below is one a verdict confirmed or the verified `pi-api-reference.md` supports.

## Detailed write-ups (top items)

### 1. Port the PubMed client to TS (`lib/lit.ts`) — Category A, the cleanest Python removal

**What changes.** Replace `beril_cli/lit_client.py` + `lit_cmd.py` with a small `lib/lit.ts` that calls PubMed `esearch.fcgi` + `esummary.fcgi` via Node's built-in `fetch`. `lit_search`/`lit_fetch` in `extensions/beril-literature.ts:63-89` then call `searchPubmed()`/`fetchArticle()` in-process instead of `berilExec(pi, ["lit","search",…])`. Drop the `lit` subparser from `beril_cli/cli.py`; `httpx>=0.27` then leaves `pyproject.toml` entirely (verified: `httpx` is imported only by the lit files + their tests), leaving `pyyaml` as the sole runtime dep.

**Pi primitive + example.** No Pi-specific HTTP primitive; Node global `fetch` + `URLSearchParams`, modeled on `examples/extensions/doom-overlay/wad-finder.ts:41` (`await fetch(url); if(!response.ok) throw; await response.json()`). The tool `execute()` already receives an `AbortSignal` (3rd arg, currently `_signal`, `types.d.ts:359`) — wire it into `fetch({signal})` plus `AbortSignal.timeout(30_000)` to preserve the 30s timeout and give real cancellation the subprocess path never had.

**Fidelity requirement (the one real trap).** Reproduce the normalizer byte-for-byte so `references.md` is identical for the same NCBI response: iterate the **`idlist`** from esearch and look up `result[pmid]` — do NOT use `Object.keys(result)` (the esummary `result` object also carries a `uids` meta-key and key order differs, which would both mis-order and try to normalize the meta-entry). `year = pubdate.split()[0]` first whitespace token; `journal = fulljournalname`; `authors = authors[].name` skipping nameless; every string defaults to `""`, authors to `[]`. Port `test_cli_lit_client.py`'s 5 normalizer cases to a TS unit test. Drop the dead `SEMANTIC_SCHOLAR_BASE` constant (defined, never called).

**Before→after hops.** TS→py1→`lit_cmd`→`lit_client`(httpx)→NCBI **→** TS→`fetch`→NCBI (no subprocess, no Python, no JSON-over-stdout reparse).

**Win.** Removes a whole runtime from the literature path; native abort support; faster failures (no subprocess spin-up before the network call). **Guardrails.** Invariant 1 improved (fewer deps, still self-contained); Invariants 2/4/5 untouched (read-only, no sha256/MCP/safety-gate). Strip-only safe (plain functions/interfaces, `.ts` extensions, `import type`). **One open verification:** does Node `fetch` reach `eutils.ncbi.nlm.nih.gov` from the off-cluster/JupyterHub network, given the pproxy/SSH tunnel is scoped to BERDL gRPC and not general HTTPS egress? Preserve the current anonymous NCBI rate posture (no `api_key`); an opt-in `NCBI_API_KEY` is a separate feature, not a port requirement.

### 3. In-process `complete()` for query expansion — Category A/B

**What changes.** `expandQueries` (`beril-literature.ts:17-28`) spawns a full second `pi` process (`pi.exec("pi",["--mode","json","--no-session",prompt])`, 180s timeout) and parses the JSONL event stream through `lib/jsonl.ts` (64 lines of fragile event-shape heuristics) just to get a JSON array of queries. Switch to in-process `complete(ctx.model, {messages}, {apiKey,headers,signal})` from `@earendil-works/pi-ai`.

**Pi primitive + example.** `complete()` at `pi-ai/dist/stream.d.ts:5`; auth via `ctx.modelRegistry.getApiKeyAndHeaders(ctx.model)` (`model-registry.d.ts:71`). Modeled exactly on `handoff.ts:136` and `summarize.ts:188-201` (content text-join). This was already documented intent (design doc:126; `pi-api-reference.md:436`) that the shipped code never adopted.

**Mandatory guard (verdict caveat).** `/literature-review` is reachable headless with `ctx.model` undefined (RPC mode; the repo's own tests). Add the `summarize.ts:163-178` fallback (`getModel("anthropic",…)` then auth; bail to the bare topic if no model/auth) and keep the existing try/catch → `[topic]`. Do NOT delete `lib/jsonl.ts` — `test/jsonl.test.ts` imports it directly; rewrite/remove those tests in the same change. **Before→after hops.** spawn child `pi` + load all extensions + JSONL parse **→** one in-process HTTP call, abort-aware. Invariants 2/3/4/5 untouched.

### 4. `tool_result` next-step hints — tighten the analysis loop cheaply

**What changes.** A `pi.on("tool_result",…)` handler keyed on `event.toolName === "berdl_query"` appends a one-line hint (e.g. "to persist this set use `berdl_export` (guarded); to record a gotcha use `/skill:pitfall-capture`") and flags hit-the-limit cases (`returned_rows === limit_applied`).

**Verified contract (verdict caveat).** `content` is an **array** `(TextContent|ImageContent)[]` and a returned `content` REPLACES the whole array — so the handler MUST return `{ content: [...event.content, {type:"text",text:hint}] }`, never a lone block (that would wipe the real result). Return ONLY `content` (never `details`) so the verified `QueryPayload` stays byte-identical. Gate on `!event.isError`. `event.details` is typed `unknown` for custom tools — read `returned_rows`/`limit_applied` defensively (guard `limit_applied` null, where `-1`/uncapped should be null). **Win.** The model proposes the right follow-up without the user prompting; no `execute()` bloat; hops unchanged. Invariant 2 verified clean (`beril-data.ts` has zero hash logic); Invariant 5 unaffected (`tool_result` ≠ `tool_call`, runs only after a successful result).

### 5. `berdl_query` Markdown table card via `renderResult` — highest UI leverage

**What changes.** `berdl_query` builds a hand-rolled pipe-table string (`lib/render.ts:renderTable`) into `result.content` text (`beril-data.ts:32`), so the TUI shows a flat untruncated monospace dump AND the model ingests the whole table. Add a `renderResult` that builds a width-aware, themed Markdown table from `result.details.rows`, with a collapsed `N rows × M cols` summary and the full grid only when expanded; keep `content` text a small textual summary for the LLM.

**Pi primitive + example.** `ToolDefinition.renderResult(result,{expanded,isPartial},theme,ctx)` (`types.d.ts:363`); `new Markdown(text,1,1,getMarkdownTheme())` (`summarize.ts:125-129`); expanded-gating (`built-in-tool-renderer.ts:59-91`); details-reading (`structured-output.ts:46-60`).

**Mandatory guard (verdict caveat — silent corruption).** The Markdown component hands text to the GFM `marked` lexer. Reusing `renderTable`'s unescaped output was reproduced byte-for-byte to DROP cells containing `|` (`"a|b"` → `b` promoted into the next column) and split rows on embedded `\n` — a perfectly-aligned table showing the WRONG values, more dangerous than today's obvious pipe dump. Fix: build from `details.rows`, escape each cell (`|`→`\|`, collapse `\n`/`\r`→space), add a regression check that a `|`-cell and a `\n`-cell round-trip to the correct row/column count. **Win.** The most-used tool gets a real data card; `content` to the LLM can shrink, lowering token cost. Render-only — no invariant touched if the escaping guard lands (risk medium without it).

### 7 & 8. Kill the redundant `beril env` re-exec (context injection + readiness cache)

**The core workflow waste.** `requireReady` (`lib/readiness.ts:19`) re-execs `beril env --json` at the top of `berdl_query`, `berdl_discover`, `berdl_export` (`beril-data.ts:28,45,65`) and `lakehouse_submit`, and `refreshStatus` runs it again on session_start + `/berdl-connect` + `/berdl-status`. A single `berdl_query` is ~4 Python starts (2 for the readiness precheck + 2 for the query). The verdict on #8 confirmed `appendEntry`/`getBranch` work headless (unlike `setStatus`) and that the event bus is one shared instance — so beril-env can be the single readiness owner, persist a `beril-readiness` snapshot, and emit `beril:readiness`; data/governance replay the snapshot on session_start and gate on the cached `ready` flag.

**Guards (both verdicts):** keep the snapshot a fast-path, not authority — `requireReady` retains its exec fallback when no snapshot exists, and `beril query` still fails loudly so a stale `ready=true` after a tunnel drop can't mask a dead connection. Persist only on change. For #7, add a real module-level TTL cache (the dossier's "reuse the cached readiness" is fictional — `refreshStatus` has no cache and early-returns headless) and APPEND to `event.systemPrompt`. The session_start de-dup is a TUI-only win (beril-env already skips the exec when `!ctx.hasUI`); the headless win is purely `requireReady` consulting the cache. **Win.** Removes a full subprocess hop from the front of every data tool call and gives the model live BERDL state without an explicit `berdl_env_check`.

### 14. `ctx.ui.custom` confirm overlay for the safety gate — make the dangerous moment legible

**What changes.** The central gate (`beril-safety.ts:19`) and `/submit` use a bare two-line `ctx.ui.confirm` that shows neither the destination `s3a://` path/overwrite mode (for `berdl_export`) nor the `archive_key`/`file_count`/ORCID (for `lakehouse_submit`). Replace with a `ctx.ui.custom` overlay rendering those consequential facts before approval.

**Verified mode branching (confirmed).** In `mode==="rpc"`, `ctx.ui.custom` returns `undefined` (does not throw), but `ctx.ui.confirm` is fully wired. The mandatory order is: (1) `if(!ctx.hasUI) return {block:true}` FIRST (covers print/json, preserves Invariant 5); (2) `if(ctx.mode==="tui")` → await overlay; (3) else (rpc) → `await ctx.ui.confirm`. Treat overlay `undefined`/Esc as deny. Apply the identical split to `/submit` (`beril-governance.ts:148-156`). Modeled on `overlay-test.ts:17-149` + `summarize.ts:117-142`. **Win.** The most irreversible actions show their real consequences at the moment of approval. The only hazard is getting the branch order wrong (an unconditional `custom()` bricks the rpc prompt path); hashes/self-containment are not in play. Extract a shared helper in `lib/destructive.ts` that takes facts + ctx and returns boolean.

## Verification notes (how this report was produced)

Produced by a 27-agent parallel investigation against the installed `@earendil-works/pi-coding-agent` 0.78.1 (`dist/**/*.d.ts`, `docs/`, the 66 `examples/extensions/*.ts`) and the repo: **9 Discover investigators** (5 mapping Pi primitives to their modeling examples, 4 auditing portability/hops), then **16 adversarial verifications** of every invariant-risking claim (**2 refuted, 8 caveat, 6 confirmed**), then synthesis. Every API claim above cites a verdict or the verified `pi-api-reference.md`.

Two completeness caveats:

- **One Discover agent** (pure-logic portability of `lifecycle.py` / `notebook_hash.py` / env-readiness / identity) failed to emit structured output and was excluded. Its domain is covered by the adjacent BERDL-bound-Python and hop/duplication audits — the Keep-in-Python rows for the hash, the lifecycle state machine, and the ORCID oracle, plus recs #22 / #23 / #28 — and by the direct empirical check below. The conservative conclusion (keep all of it in Python) is unaffected; a re-run would only reconfirm it.
- **Notebook-hash byte-identity, verified by direct test** (not merely asserted). Comparing Python `json.dumps(sort_keys=True, separators=(",",":"), ensure_ascii=False).encode("utf-8")` against Node `JSON.stringify(...)`:
  - Compact separators and `ensure_ascii=False` UTF-8 output **match** — so a blanket "JS ≠ Python" is too strong, and (with sorted keys) many ASCII/BMP inputs hash identically.
  - They **diverge** on (a) **integer-valued floats** — Python `{"a":1.0}` → `{"a":1.0}`, Node → `{"a":1}`; and (b) **supplementary-plane key sort order** — for a `U+1F600` key vs a `U+E000` key, Python sorts by code point (emoji last) while JS `Array.sort()` sorts by UTF-16 code unit (emoji first), producing different byte order.
  - Either divergence changes the SHA-256, so the canonical-JSON hash **must stay in Python** (Invariant 2). Confirmed: no recommendation in this report recomputes a hash in TS — all consume the hex as opaque strings.
